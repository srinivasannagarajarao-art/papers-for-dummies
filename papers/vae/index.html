Auto-Encoding Variational Bayes (the VAE)

Kingma and Welling, 2013

An autoencoder whose bottleneck is a bell curve instead of a number. Explained as code, because that's how I finally read it.

Download vae_from_scratch.py — everything below runs from it. NumPy for the mechanism, plus a tiny CPU PyTorch model for the training step.

I'm an AI Engineer. I've shipped a VAE without noticing — Stable Diffusion's pixels come out of a VAE decoder — and I still couldn't read this paper. Pages of Bayesian notation, and the two ideas that matter are three lines of arithmetic each. Nobody told me the rest is a proof that those three lines are allowed.

A VAE is lossy compression with a rule about the codes

You've built this:

code  = compress(x)          # squeeze the input down to a few numbers
x_hat = decompress(code)     # rebuild it
loss  = how_far_off(x, x_hat)

That's an autoencoder. It compresses fine. What it cannot do is generate: hand the decompressor a random code and you get junk, because the codes live wherever the compressor felt like putting them — a shape nobody wrote down, in a region nobody can find again.

The VAE makes two changes:

mu, log_var = encoder(x)                   # not a code: a bell curve of codes
z     = mu + exp(0.5 * log_var) * randn()  # pick one code from that curve
x_hat = decoder(z)
loss  = how_far_off(x, x_hat) + kl(mu, log_var)  # + "codes must look like N(0,1)"

The compressor returns a distribution, and there's a tax whenever that distribution doesn't look like standard normal noise. Pay the tax all through training and afterwards any standard normal noise you draw is a valid code: decode it and you get a new, plausible input. That's the generative trick.

TermMeansProgrammer's analogy
Encoder q(z|x)Takes x, returns (μ, log σ²): the centre and width of a bell curveA compressor that returns a range, not a value
Decoder p(x|z)Takes a code z, rebuilds xThe decompressor. An ordinary MLP
Latent zOne code, sampled from the bell curveThe compressed bytes
Prior p(z) = N(0, I)What codes are supposed to look likeThe schema the codes must validate against
KL termHow far the encoder's bell curve is from N(0, I)The linter that fails the build when a code breaks the schema

The one formula

log p(x) ≥ Ez ~ q(z|x)[ log p(x|z) ] − KL( q(z|x) ‖ N(0, I) )

The right-hand side is the ELBO, the bound in section 2.2 of the paper. Training maximises it, so the loss is its negative: reconstruction plus tax. Two helpers make it computable:

z = μ + σ ⊙ ε, ε ~ N(0, I) KL = −½ Σ (1 + log σ² − μ² − σ²)

Read it as pipeline stages:

StepShapeWhat it does
encoder(x)(n, dz) twiceTwo heads on one MLP: μ and log σ². A bell curve per input
ε ~ N(0, I)(n, dz)The dice. Drawn outside the model. No parameters, no gradient
z = μ + exp(½ log σ²) ε(n, dz)The trick. Add and multiply. Backprop walks through this
decoder(z)(n, dx)Rebuild the input from the code
‖x − x̂‖² / 2σx²(n,)Reconstruction. −log p(x|z) for a Gaussian decoder — MSE is a likelihood in disguise
−½ Σ(1 + log σ² − μ² − σ²)(n,)The tax. KL to N(0, I), closed form, the paper's Appendix B
mean(recon + KL)scalar−ELBO. Then loss.backward()

One thing the table hides. A decoder whose output is the mean of a Gaussian with fixed std σx has −log p(x|z) = squared error / 2σx² plus a constant. So "MSE" is the paper's likelihood term, and σx is the exchange rate between reconstruction and tax. I fixed it at 0.1; change it and you've changed the KL weight without touching the KL.

The trick: move the dice outside the function

You want z drawn from N(μ, σ²), and you want loss.backward() to reach μ and σ. But rng.normal(mu, sigma) is a black box: the randomness happens inside it, so there's no function of μ to differentiate. Nudge μ and z moves by a random amount, not by a derivative.

The fix is to draw the randomness first, from a distribution with no parameters, then turn it into z with arithmetic: eps = randn(), then z = mu + sigma * eps. Same distribution for z. But now dz/dμ = 1 and dz/dσ = ε, and backprop walks straight through. That's section 2.4, and it's the reason the paper exists: the older score-function estimator "exhibits very high variance", in the paper's own words, and this replaces it with plain backprop. The other contribution the introduction lists is the encoder itself — a recognition model that answers inference in one forward pass, instead of an optimisation loop per datapoint. A cache for the expensive per-item computation.

Don't take my word for it. Here's the actual output:

want N( 1.50, 0.40)   100000 draws of mu + sigma*eps:  mean  1.500  std 0.401
want N(-2.00, 3.00)   100000 draws of mu + sigma*eps:  mean -1.998  std 3.003

now the gradient. dz/dmu by finite difference, (z(mu+h) - z(mu)) / h
  'direct' = two separate rng.normal(mu, sigma) calls, fresh dice each
  h=0.1    reparam:  1.000   direct once:    -2.786   direct rms/1000:     5.9
  h=0.01   reparam:  1.000   direct once:     4.828   direct rms/1000:    57.0
  h=0.001  reparam:  1.000   direct once:  -247.014   direct rms/1000:   554.6
  dz/dsigma, reparameterised: -1.224   and eps was -1.224

Shrink h and the direct version gets worse, not better — it's noise of size σ divided by h; there is no derivative there to find. Reparameterised, it's exactly 1, and dz/dσ is exactly the ε that was rolled. And the reason every implementation says exp(0.5 * log_var): a raw network output can be negative, a standard deviation can't, so the encoder emits log σ² and the exp makes σ positive by construction.

In PyTorch this is the difference between Normal(mu, sigma).sample() and .rsample(). sample() returns a tensor with no grad_fn; rsample() returns mu + sigma * eps with an AddBackward0. The r is this paper.

The tax: KL to a standard normal, in one line

KL(q ‖ p) is "how surprised p would be by q's samples", in nats. For q = N(μ, σ²) against p = N(0, 1) it's the one-liner in the formula above: zero at μ = 0, σ = 1, bigger the further you move, summed over latent dimensions.

The closed form, checked against a 200,000-sample estimate:

The row to stare at is (0.0, 0.1). A narrow bell curve is taxed too — 1.8 nats for shrinking σ to 0.1. That's what stops the VAE quietly turning itself back into a plain autoencoder with σ = 0. It has to pay for precision, and it will only pay where precision buys reconstruction.

Training: watch the two terms fight

The toy data is 512 points on a unit ring with a little radial noise — one-dimensional structure living in 2-D. Two-layer MLPs, a 2-D latent, Adam, full batch, 1500 steps on a CPU. One ε per datapoint per step, which section 2.3 of the paper says is enough when the batch is large. 

step     0  loss   53.213  recon   53.199  kl  0.014  mse 1.0640
step   250  loss    4.206  recon    0.922  kl  3.284  mse 0.0184
step   500  loss    4.069  recon    0.917  kl  3.152  mse 0.0183
step  1000  loss    4.077  recon    0.886  kl  3.191  mse 0.0177
step  1500  loss    3.982  recon    0.750  kl  3.232  mse 0.0150

reconstruction mse, z = mu (no noise):      0.0033
reconstruction mse, z sampled from q(z|x): 0.0165
encoder's mean sigma 0.231, mean |mu| 0.878, KL per point 3.232 nats

Step 0 is worth a look. A fresh encoder already outputs roughly N(0, 1), so the tax is nearly zero (0.014) and the decoder predicts the origin for everything: mse 1.064, about the data's own spread. Then the encoder buys information — the KL climbs to about 3.2 nats and stays there, and reconstruction falls over 300× to 0.0033. The tax never reaches zero; it settles where the next nat of precision stops paying for itself.

The generative claim: noise in, ring out

This is the test a plain autoencoder fails. Draw 2000 z's from N(0, I) — numbers that have never seen the data — decode them, and measure the radius of what comes out. "on ring" is the fraction within 0.1 of radius 1. 

                       radius mean radius std  on ring
the data                     0.996      0.047    0.969
raw noise, no decoder        1.260      0.666    0.126
decoded prior noise          0.947      0.122    0.856

Raw 2-D noise lands on the ring 12.6% of the time, by accident. Pass the same noise through the decoder and 85.6% lands. The decoder has only ever seen codes that came from real points; it works on fresh noise because the tax forced those codes to look like fresh noise.

0.856, not 0.969. The samples' radius spreads 0.122 against the data's 0.047. That's the VAE blur, in 2-D: a likelihood objective is minimised by the average of everything consistent with a code, so uncertainty comes out as a smear. GANs don't average, which is why their samples look crisper.

β: the dial between compression and fidelity

The paper has no β; the KL weight is 1 because that's what the bound says. β-VAE (Higgins et al., 2017) made it a dial, and turning it is the fastest way to feel what the tax is for. Same model, data and steps. "mse" is reconstruction with z = μ; "recon std" is how spread out the reconstructions are. 

                         mse      kl   sigma   |mu| recon std  on ring
beta=1 (the paper)    0.0033   3.232   0.231   0.88     0.703    0.856
beta=0, no KL         0.0002  11.069   0.005   1.07     0.704    0.189
beta=4 (beta-VAE)     0.0047   2.319   0.334   0.86     0.690    0.826
beta=50, huge KL      0.9084   0.036   0.981   0.14     0.033    0.000
(data itself)                                           0.704    0.969
(raw noise, undecoded)                                             0.126

β = 0 is the plain autoencoder: best reconstruction, and prior noise lands on the ring 18.9% of the time — barely above the 12.6% with no decoder at all. β = 4 is the β-VAE regime: samples still land, at the price of a 40% blurrier reconstruction; on this toy, push past about β = 8 and the samples go too. β = 50 is posterior collapse: σ → 1, μ → 0, and every reconstruction is nearly the same point.

The code

NumPy for the mechanism: the trick and the KL, three lines each. A tiny PyTorch model, CPU only, trains seven variants in about 15 seconds. The torch version of the trick is one line inside train_vae, with the deliberate bugs next to it behind a flag.

Download the full script — about 200 lines plus four runnable demos. Then: 

python3 vae_from_scratch.py
# ---------------------------------------------------------------------------
# STAGE 1 -- THE TRICK. Section 2.4 of the paper.
#
# You want z ~ N(mu, sigma^2), and you want gradients to flow back into mu and
# sigma. A call like rng.normal(mu, sigma) is a black box: the randomness
# happens INSIDE it, so there is no function of mu to differentiate.
#
# Fix: draw the randomness first, from a distribution that has no parameters,
# then turn it into z with plain arithmetic.
#
#     eps ~ N(0, 1)              # the dice roll. No parameters. No gradient.
#     z   = mu + sigma * eps     # add and multiply. Backprop walks through this.
#
# dz/dmu = 1, dz/dsigma = eps. Same distribution for z, but now differentiable.
# The encoder outputs log(sigma^2), not sigma, so sigma = exp(0.5 * log_var)
# is positive by construction and can never go negative.
# ---------------------------------------------------------------------------
def reparameterise(mu, log_var, eps):
    sigma = np.exp(0.5 * log_var)
    return mu + sigma * eps

# ---------------------------------------------------------------------------
# STAGE 2 -- THE TAX. KL( N(mu, sigma^2) || N(0, 1) ), closed form, Appendix B.
#
#     KL = -1/2 * sum( 1 + log(sigma^2) - mu^2 - sigma^2 )
#
# Zero when mu=0 and sigma=1. Grows as the bell curve moves or changes width.
# This is the penalty for a code not looking like standard normal noise.
# Summed over latent dimensions, because the dims are independent.
# ---------------------------------------------------------------------------
def kl_standard_normal(mu, log_var):
    return -0.5 * np.sum(1 + log_var - mu ** 2 - np.exp(log_var), axis=-1)

SIGMA_X = 0.1


def elbo_loss(x, x_hat, mu, log_var, beta=1.0):
    recon = ((x - x_hat) ** 2).sum(dim=-1) / (2 * SIGMA_X ** 2)
    kl = -0.5 * (1 + log_var - mu ** 2 - log_var.exp()).sum(dim=-1)
    return (recon + beta * kl).mean(), recon.mean(), kl.mean()

Then read the paper — but only §2.2 to §2.4 (the bound, the estimator, the trick), Appendix B (the KL one-liner) and §3 (the actual VAE). Skip the appendices on full variational Bayes and the marginal-likelihood estimator. You'll find the paper is just the comments you've already read.

On the maths anxiety

This paper needs four things. An expectation is an average over samples — a for loop and a mean, which is all "Monte Carlo" means. A log turns products into sums, which is why everything is a log-likelihood and why MSE shows up. A Gaussian is two numbers per dimension. And KL is a distance-ish score between two distributions which, for two Gaussians, is a one-liner you copy from Appendix B. What you don't need is to derive the bound: that's one step, Jensen's inequality, "log of an average ≥ average of logs", and you can use the loss for the rest of your career without reproving it — the same way you use loss.backward() without deriving backprop.

The interview question you'll be asked is "why the reparameterisation trick?" One sentence: you can't backprop through a random number generator, so move the sampling out to a parameter-free ε and make z a deterministic function of μ, σ and ε. The follow-up is "why are VAE samples blurry?" — the likelihood objective averages over everything consistent with a code. You've now seen both happen.

Where to go next
