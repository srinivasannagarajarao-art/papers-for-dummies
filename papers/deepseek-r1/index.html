DeepSeek-R1: reasoning nobody taught it

DeepSeek-AI, 2025

Nobody wrote the reasoning examples. Nobody rewarded length. The working-out showed up anyway, and that is the whole story.

Download deepseek_r1_from_scratch.py — everything below runs from it. NumPy for the environment, plus a tiny CPU PyTorch policy for the GRPO training loop. About 20 seconds.

Blunt about the limits first, the same way the chain-of-thought page and the RAG page are about their stand-ins. There is no language model in my script. A four-input MLP cannot demonstrate emergent reasoning in a 671-billion-parameter model, and nothing it prints is evidence about what R1 does on a maths olympiad problem.

What it can show, honestly, is the mechanism the result stands on: when a correctness-only reward is paired with a task where more steps genuinely help, a policy gradient discovers longer solutions without anybody telling it to. That claim fits on a laptop. Every number below is from that analogy, and I say so each time.

I had this paper filed under "another RLHF variant" for months. It isn't. The interesting model in it is R1-Zero, and what makes it interesting is a deletion.

You paid for correct answers and got the working-out for free

You have shipped this function:

def solve(question):
    return model(question)      # one forward pass. no locals, no loop.

And you know the fix from chain-of-thought: give it somewhere to put intermediate values, because every token it emits becomes part of its own next input. Emitted tokens are serial compute. So you write exemplars that show the working, and the continuation shows its working too.

R1-Zero is what happens when you refuse to write those exemplars:

def solve(question):
    scratch = []
    while keep_going(scratch):          # nobody wrote this loop
        scratch.append(step(question, scratch))
    return final(scratch)

reward = 1.0 if answer_is_right else 0.0     # this is all you paid for

Take a base model. Skip supervised fine-tuning entirely. Score its output with a rule — is the answer right, is it in the required tags — and run reinforcement learning. Long chains of reasoning appear on their own, including the model stopping to re-check its own working. The paper's framing is that the reasoning was incentivised, not taught.

It's the contractor you pay per correct answer with no time limit. They start showing their working, not because you asked for working, but because checking themselves is the cheapest route to the thing you're paying for. The optimiser found the same trade.

What it deleted from the InstructGPT pipeline

InstructGPT is three stages: supervised fine-tuning on human demonstrations, then a reward model trained on human comparisons, then PPO against that reward model. Two of those three stages need people, and the second one has the failure mode the RLHF page is entirely about — the optimiser hunting for the soft spots in a learned model of the tester.

R1-Zero deletes both.

StageInstructGPTR1-Zero
DemonstrationsHumans write ideal answers, SFT on themSkipped
RewardReward model learned from human comparisonsA rule. Is the answer right, are the tags there
OptimisationPPO with a KL penalty to the SFT modelGRPO with a KL penalty to the reference

You can only delete them because maths and code answers are checkable. There is a right answer and a script can tell. That is the boundary of the method, and it is worth saying out loud in an interview: rule-based rewards work where a unit test works.

The one formula

Two sentences of GRPO, because the GRPO page derives it properly and I'm not re-deriving it here. Sample a group of G answers to the same prompt, score them all, and use each answer's score minus the group's mean, over the group's standard deviation, as its advantage — so the group is the baseline and there is no value network to train. Then it is the ordinary policy gradient, with a KL leash back to a frozen reference.

Âi = (ri − mean(r1..G)) / std(r1..G)   ·   J = E[ Âi · log πθ(oi) ] − β · KL(πθ ‖ πref)

Notice what the reward does not contain. There is no term for length, no term for "reasoning quality", no term for style. If length is going to appear, it has to appear because of the correctness term.

First, prove that thinking longer actually helps

If it doesn't, nothing else on this page means anything — so my toy task is built so that it genuinely does. Each problem is one true digit and six noisy readings of it, each reading correct 55% of the time. The policy chooses, step by step, whether to read once more or stop and answer with the majority of what it has read. There are only six real readings; step seven onwards re-reads one it already has, which is not new information and double-counts whatever noise it lands on.

That is the mechanism, and it is also the honest boundary of the claim: my script shows why the optimiser would lengthen output, not that a transformer's chain-of-thought is doing anything as tidy as this.

Reward design, which is where you will actually go wrong

Three reward functions, everything else identical. This is the section I would put on a whiteboard if someone asked me what I learned from R1. 

  reward function                  accuracy   mean length   format
  correct + format                   0.850        5.12       1.00
  format ONLY                        0.360        1.12       1.00
  correct + format + 0.05*length     0.743       16.00       1.00

Format only gets you perfectly structured output with the accuracy of a ten-sided coin. It never learned to look at the answer, because nothing ever paid it to. Every field validates. Nothing is true.

Length in the reward gets you padding. It runs to the context window and accuracy falls — 0.850 down to 0.743 — because the extra steps are re-reads, and re-reads amplify noise. You bought tokens and called it thought. This is why R1's reward has no length term: length is a symptom you want, not a target you set.

The tags, the parser, and the bug you will ship

R1's template is thinking between <think> tags and the final answer between <answer> tags, so a rule can find the answer without guessing. Mine copies that: 

<think>
step 1: read -> 9
step 2: read -> 8
step 3: read -> 9
step 4: read -> 5
step 5: read -> 9
step 6: read -> 9
</think>
<answer>9</answer>

   truth                       : 9
   parse_answer (tag-anchored) : 9
   parse_answer_broken (first  : 1   <- that's the step index
     number anywhere)

Now break the parser the way everyone breaks it once — match the first number anywhere in the output instead of the one inside the answer tags. Same model, same rollouts, two graders: 

   scored with the correct parser : 0.850
   scored with the broken parser  : 0.090

   trained AGAINST the broken parser -> real accuracy 0.330, length 1.17

The second number is the parser's opinion of the working-out, not the answer. Grade with it and you have not measured a worse model, you have measured a different string. Train against it and the reward signal is noise, so the policy learns to stop early and stops learning anything at all. A regex is a component of your training objective. Treat it like one.

Distillation, and why R1 needed a cold start

The paper's other finding is that distilling R1's outputs into smaller dense models worked better than running large-scale RL on those small models directly. My version of that, matched on rollouts of the environment rather than on gradient steps, because rollouts are the expensive part: 

  teacher  (hidden=16, 150 GRPO iters)   acc 0.850   length   5.12
  kept 1051/1200 teacher rollouts -> 6446 labelled decisions

  small network, hidden=4:
    distilled from teacher, 0 new rollouts   acc 0.850   length   5.02
    GRPO directly, 18 iters (1152 rollouts)  acc 0.485   length   2.02
    GRPO directly, 150 iters (9600 rollouts) acc 0.823   length   5.47

Every successful teacher trajectory hands the student a label for every decision inside it. A reward hands it one scalar for the whole trajectory. That is the entire difference. Give the RL student eight times the rollouts and it catches up — which is exactly the trade the paper is pointing at. Matched on gradient steps instead, my two students are within noise of each other, so treat this as an analogy for their result rather than evidence of it.

And this is why R1-Zero is not the model they shipped. R1-Zero's answers were right and hard to read — poor readability, and languages mixed together inside a single chain of thought. So R1 proper adds a small cold-start supervised stage before the RL, purely to fix how the output reads. The emergence is real; it just doesn't arrive housetrained.

Paper-ன் மற்றொரு கண்டுபிடிப்பு: R1-ன் outputs-ஐ சிறிய dense models-க்குள் distil செய்வது, அந்தச் சிறிய models மேல் நேரடியாக பெரிய அளவில் RL ஓட்டுவதை விட நன்றாக வேலை செய்தது. அதன் என் பதிப்பு — gradient steps அடிப்படையில் அல்ல, environment-ன் rollouts அடிப்படையில் ஒப்பிட்டது, ஏனெனில் விலை உயர்ந்த பகுதி rollouts தான்: 

  teacher  (hidden=16, 150 GRPO iters)   acc 0.850   length   5.12
  kept 1051/1200 teacher rollouts -> 6446 labelled decisions

  small network, hidden=4:
    distilled from teacher, 0 new rollouts   acc 0.850   length   5.02
    GRPO directly, 18 iters (1152 rollouts)  acc 0.485   length   2.02
    GRPO directly, 150 iters (9600 rollouts) acc 0.823   length   5.47

வெற்றி பெற்ற ஒவ்வொரு teacher trajectory-ம், அதற்குள் உள்ள ஒவ்வொரு முடிவுக்கும் ஒரு label-ஐ student-க்குக் கொடுக்கிறது. ஒரு reward, முழு trajectory-க்கும் சேர்த்து ஒரே ஒரு scalar-ஐத்தான் கொடுக்கிறது. முழு வித்தியாசமும் அதுதான். RL student-க்கு எட்டு மடங்கு rollouts கொடுத்தால் அது பிடித்துவிடுகிறது — paper சுட்டிக்காட்டும் பேரம் சரியாக அதுதான். Gradient steps அடிப்படையில் ஒப்பிட்டால், என் இரண்டு students-ம் noise-க்குள் ஒரே மாதிரி; எனவே இதை அவர்களுடைய முடிவுக்கான ஆதாரமாக அல்ல, ஒரு ஒப்புமையாக மட்டுமே எடுத்துக்கொள்ளுங்கள்.

இதனால்தான் அவர்கள் ship செய்தது R1-Zero அல்ல. R1-Zero-ன் விடைகள் சரியாக இருந்தன, ஆனால் படிப்பதற்குக் கடினமாக இருந்தன — readability மோசம், ஒரே chain of thought-க்குள் மொழிகள் கலந்திருந்தன. எனவே R1, RL-க்கு முன் ஒரு சிறிய cold-start supervised நிலையைச் சேர்க்கிறது — output எப்படிப் படிக்கிறது என்பதை மட்டும் சரி செய்ய. அந்த வெளிப்பாடு உண்மையானது; அது பழக்கப்படுத்தப்பட்ட நிலையில் வருவதில்லை, அவ்வளவுதான்.

सीमाएँ पहले, बिना लाग-लपेट के — ठीक वैसे ही जैसे chain-of-thought page और RAG page अपने stand-in के बारे में कहते हैं। मेरी script में कोई language model है ही नहीं। चार input वाला एक छोटा MLP यह नहीं दिखा सकता कि 671 अरब parameter वाले model में reasoning अपने आप उभरती है, और वह जो कुछ भी print करता है वह इस बात का सबूत नहीं है कि R1 किसी maths olympiad सवाल पर क्या करता है।

ध्यान दें: English technical words (reward, format, parser, rollout, policy, GRPO, KL, cold start, distillation, chain-of-thought…) मैंने वैसे ही रखे हैं। क्योंकि code में और बाक़ी papers में आपको वही शब्द दिखेंगे। समझ हिंदी में, शब्दावली English में।

लेकिन ईमानदारी से वह एक चीज़ दिखा सकती है — वह तंत्र जिस पर यह नतीजा टिका है: जब सिर्फ़ correctness देखने वाले reward को ऐसे task के साथ जोड़ा जाए जहाँ ज़्यादा steps सचमुच मदद करते हैं, तो policy gradient बिना किसी के कहे लंबे हल खोज निकालता है। यह दावा एक laptop पर चल जाता है। नीचे का हर आँकड़ा उसी analogy से आया है, और हर बार मैं यह कह भी देता हूँ।

महीनों तक यह paper मेरे लिए "एक और RLHF variant" था। है नहीं। इसमें दिलचस्प model R1-Zero है, और उसे दिलचस्प बनाती है एक कटौती।

आपने सही जवाब का पैसा दिया और काम दिखाना मुफ़्त में मिल गया

यह function आप ship कर चुके हैं:

def solve(question):
    return model(question)      # एक forward pass. न locals, न loop.

और इसका इलाज आपको chain-of-thought से पता है: उसे बीच के मान रखने के लिए जगह दीजिए, क्योंकि वह जो भी token निकालता है वह उसके अगले input का हिस्सा बन जाता है। निकाले गए tokens ही serial compute हैं। तो आप ऐसे exemplars लिखते हैं जो काम करके दिखाते हैं, और फिर उसका continuation भी अपना काम दिखाने लगता है।

R1-Zero वही है जो तब होता है जब आप वे exemplars लिखने से मना कर दें:

def solve(question):
    scratch = []
    while keep_going(scratch):          # यह loop किसी ने नहीं लिखा
        scratch.append(step(question, scratch))
    return final(scratch)

reward = 1.0 if answer_is_right else 0.0     # पैसा सिर्फ़ इसी का दिया

एक base model लीजिए। supervised fine-tuning पूरी तरह छोड़ दीजिए। उसके output को एक नियम से score कीजिए — जवाब सही है क्या, ज़रूरी tags में है क्या — और reinforcement learning चलाइए। लंबी reasoning शृंखलाएँ अपने आप आ जाती हैं, यहाँ तक कि model रुककर अपना ही काम दोबारा जाँचने लगता है। Paper का कहना है कि reasoning सिखाई नहीं गई, उसे प्रोत्साहित किया गया।

वह ठेकेदार सोचिए जिसे आप हर सही जवाब का पैसा देते हैं और समय की कोई सीमा नहीं रखते। वह अपना काम दिखाने लगता है — इसलिए नहीं कि आपने काम दिखाने को कहा, बल्कि इसलिए कि ख़ुद को जाँचना उस चीज़ तक पहुँचने का सबसे सस्ता रास्ता है जिसका आप पैसा दे रहे हैं। Optimiser ने भी वही सौदा ढूँढ़ लिया।

वह इकलौता सूत्र

सिर्फ़ format से आपको बिल्कुल सही ढाँचे वाला output मिलता है, accuracy दस-पहलू वाले सिक्के जितनी। उसने जवाब देखना सीखा ही नहीं, क्योंकि उसका पैसा कभी किसी ने नहीं दिया। हर field validate होता है। कुछ भी सच नहीं है।

Reward में length डालिए तो padding मिलेगी। वह context window तक चला जाता है और accuracy गिरती है — 0.850 से 0.743 — क्योंकि अतिरिक्त steps दोबारा पढ़ना हैं, और दोबारा पढ़ना noise को बढ़ाता है। आपने tokens ख़रीदे और उसे सोच कह दिया। इसीलिए R1 के reward में कोई length term नहीं है: length एक लक्षण है जो आप चाहते हैं, वह लक्ष्य नहीं जो आप तय करते हैं।

Distillation, और R1 को cold start क्यों चाहिए था

Paper की दूसरी खोज यह है कि R1 के outputs को छोटे dense models में distil करना, उन्हीं छोटे models पर सीधे बड़े पैमाने की RL चलाने से बेहतर रहा। इसका मेरा संस्करण, gradient steps के बजाय environment के rollouts पर मिलाया गया, क्योंकि महँगा हिस्सा rollouts ही हैं: 

  teacher  (hidden=16, 150 GRPO iters)   acc 0.850   length   5.12
  kept 1051/1200 teacher rollouts -> 6446 labelled decisions

  small network, hidden=4:
    distilled from teacher, 0 new rollouts   acc 0.850   length   5.02
    GRPO directly, 18 iters (1152 rollouts)  acc 0.485   length   2.02
    GRPO directly, 150 iters (9600 rollouts) acc 0.823   length   5.47

teacher की हर सफल trajectory student को उसके भीतर के हर फ़ैसले का एक label दे देती है। एक reward पूरी trajectory के लिए बस एक scalar देता है। पूरा फ़र्क़ यही है। RL वाले student को आठ गुना rollouts दीजिए और वह बराबरी कर लेता है — और paper ठीक इसी सौदे की ओर इशारा कर रहा है। Gradient steps पर मिलाने पर मेरे दोनों students शोर के भीतर एक जैसे हैं, इसलिए इसे उनके नतीजे का सबूत नहीं, उसकी analogy मानिए।

और इसीलिए R1-Zero वह model नहीं है जो उन्होंने ship किया। R1-Zero के जवाब सही थे मगर पढ़ने में मुश्किल — readability ख़राब, और एक ही chain of thought के भीतर भाषाएँ मिली हुई। इसलिए असली R1, RL से पहले एक छोटा cold-start supervised चरण जोड़ता है, सिर्फ़ यह ठीक करने के लिए कि output पढ़ने में कैसा लगता है। उभरना असली है; बस वह सधा-सधाया आकर नहीं मिलता।

The code

NumPy for the environment, the majority vote and the parsers. A tiny PyTorch policy — four inputs, sixteen hidden units, three actions — CPU only, for the GRPO loop, because hand-writing backprop through 150 iterations would bury the one thing worth looking at. Every function under 25 lines.

N_DIGITS = 10        # answers are digits 0-9
N_READINGS = 6       # how much genuine evidence a problem contains
K_MAX = 16           # the context window: a hard stop, not a penalty
P_CORRECT = 0.55     # per-reading accuracy on the hard task
BETA = 0.1           # default KL leash (swept in demo 5)

CONTINUE, STOP_TAGGED, STOP_RAW = 0, 1, 2


# STAGE 0 -- the environment. A problem is a truth plus six noisy readings.
# Reading k for k < 6 is fresh evidence. Reading 7, 8, 9... is a re-read of
# something already seen: no new information, and it double-counts whatever
# noise it happens to land on.
def make_problem(rng, p_correct=P_CORRECT):
    truth = int(rng.integers(N_DIGITS))
    readings = []
    for _ in range(N_READINGS):
        if rng.random() < p_correct:
            readings.append(truth)
        else:
            step = 1 + int(rng.integers(N_DIGITS - 1))
            readings.append((truth + step) % N_DIGITS)
    return truth, readings


def next_reading(rng, readings, seen):
    """Fresh evidence while there is any left, otherwise a re-read."""
    if len(seen) < N_READINGS:
        return readings[len(seen)]
    return seen[int(rng.integers(len(seen)))]


def majority(seen):
    """The answer readout. NOT learned -- the policy only decides when to stop."""
    if not seen:
        return -1
    return int(np.bincount(seen, minlength=N_DIGITS).argmax())


# STAGE 1 -- what the policy sees. Four numbers: how much context is spent, how
# decisive the current vote is, how big the leading count is, and a bias term.
# Deliberately tiny, so nothing interesting can hide inside the network.
def features(seen):
    k = len(seen)
    if k == 0:
        return [0.0, 0.0, 0.0, 1.0]
    counts = np.sort(np.bincount(seen, minlength=N_DIGITS))[::-1]
    return [k / K_MAX, (counts[0] - counts[1]) / k, counts[0] / k, 1.0]


# STAGE 2 -- the output format. R1 asks for thinking between <think> tags and
# the final answer between <answer> tags, so that a rule -- not a learned
# reward model -- can grade it. STOP_RAW emits the same content with no tags,
# which is the degree of freedom the format reward exists to remove.
def render(seen, answer, tagged):
    steps = "\n".join(f"step {i + 1}: read -> {v}" for i, v in enumerate(seen))
    if tagged:
        return f"<think>\n{steps}\n</think>\n<answer>{answer}</answer>"
    return f"{steps}\nthe answer is {answer}"


ANSWER_RE = re.compile(r"<answer>\s*(\d+)\s*</answer>")
FORMAT_RE = re.compile(r"<think>.*</think>\s*<answer>.*</answer>", re.S)


def parse_answer(text):
    """Pull the final answer out of the tags. Returns None if it isn't there."""
    m = ANSWER_RE.search(text)
    return int(m.group(1)) if m else None


def parse_answer_broken(text):
    """The bug everyone ships once: first number ANYWHERE. Grabs the working."""
    m = re.search(r"(\d+)", text)
    return int(m.group(1)) if m else None


# STAGE 3 -- the reward functions. R1-Zero's is rule-based: accuracy plus
# format, no learned reward model, because a learned one invites the optimiser
# to go hunting for its soft spots (see the RLHF page). Note what is NOT here:
# any term that mentions length.
def reward_correct_format(text, truth, n_steps, parser=parse_answer):
    return 0.2 * format_ok(text) + 1.0 * (parser(text) == truth)


def reward_format_only(text, truth, n_steps, parser=parse_answer):
    return 0.2 * format_ok(text)                      # never mentions the answer


def reward_with_length(text, truth, n_steps, parser=parse_answer):
    return reward_correct_format(text, truth, n_steps, parser) + 0.05 * n_steps


# STAGE 5 -- GRPO, in one function. Two sentences: sample a group of G answers
# for each prompt, score them, and use (r - mean of the group) / (std of the
# group) as the advantage, so no value network is needed -- the group is the
# baseline. Then the usual policy gradient, plus a KL leash back to the
# reference policy. Full derivation on the GRPO page; this is the same
# estimator, in 20 lines.
def grpo_step(policy, ref, opt, roll, rewards, group, beta):
    r = torch.tensor(rewards, dtype=torch.float32).view(-1, group)
    adv = (r - r.mean(1, keepdim=True)) / (r.std(1, keepdim=True) + 1e-6)
    adv = adv.view(-1)

    x = torch.tensor(roll["feats"], dtype=torch.float32)
    logp = torch.log_softmax(policy(x), dim=-1)
    chosen = logp[torch.arange(len(roll["acts"])), torch.tensor(roll["acts"])]

    # sum the log-probs of each trajectory, weight by that trajectory's advantage
    per_traj = torch.zeros(roll["n"]).index_add_(
        0, torch.tensor(roll["owner"]), chosen)
    pg = -(per_traj * adv).mean()

    # the leash: KL(policy || reference) at every state actually visited
    with torch.no_grad():
        ref_logp = torch.log_softmax(ref(x), dim=-1)
    kl = (logp.exp() * (logp - ref_logp)).sum(-1)
    kl_traj = torch.zeros(roll["n"]).index_add_(
        0, torch.tensor(roll["owner"]), kl)

    opt.zero_grad()
    (pg + beta * kl_traj.mean()).backward()
    opt.step()
    return float(kl_traj.mean())

On the maths anxiety

There is less here than the notation suggests. The advantage is a z-score: subtract the mean of eight numbers, divide by their standard deviation. You have written that in a monitoring dashboard. It exists so the policy is told "better or worse than your siblings" rather than "your score was 0.83", which is what removes the need for a separate value network.

The policy gradient is one derivative you can take on trust: nudge up the log-probability of things that went better than average, nudge it down for things that went worse. The KL term is a distance between two probability distributions, measured in nats, and in code it is literally (p * (log p − log q)).sum(). That's it. Nothing in this paper needs a proof to be used correctly.

What does need care is not maths at all — it's the reward function and the parser that feeds it. Those are ordinary software, they are wrong in ordinary ways, and they are where the whole method succeeds or quietly fails. The question you will be asked in an interview is not how GRPO's advantage is derived. It's "how did you know the model got better, and not just better at your grader?"
