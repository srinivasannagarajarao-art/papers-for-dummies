GRPO: reinforcement learning without a critic

Shao et al., 2024 — DeepSeekMath

The second model everyone trains alongside the policy is a baseline predictor. You can get a baseline for free.

Download grpo_from_scratch.py — everything below runs from it. NumPy for the mechanism, plus a tiny CPU PyTorch loop for the training steps. Five and a half seconds.

I'm an AI Engineer. I've shipped models, done the MLOps, and when DeepSeek-R1 landed and everyone started saying "GRPO" I assumed it was a new algorithm I'd have to learn from scratch. It isn't. It's the policy gradient from the RLHF page with one line changed — the line that computes the baseline. That one line deletes a whole second neural network from your training job.

This page leans on two others. RLHF: fit a reward model to human votes, then climb it with a policy while a KL penalty keeps you near the model you started from. DPO: skip the climbing, because the optimum of that objective has a closed form you can turn into a supervised loss. InstructGPT: the three-stage pipeline all of it sits inside. I won't re-derive the reward model, the KL penalty or the policy gradient. GRPO keeps all three; it changes what you subtract.

Grading on a curve

Here is the policy gradient, the shape everyone writes first: 

for answer, reward in sampled:
    push_up(answer, by=reward)     # reward is 0..10, always positive

Spot the bug. Every reward is positive, so every sampled answer gets pushed up — the good ones and the bad ones alike. The differences are what you meant to learn, and they're a ripple on a large constant. It converges; practically, it's noise. So you subtract something. PPO's answer: hire a second examiner. Train a value network — a critic, roughly the size of the policy — to predict what this prompt should score, and subtract its prediction. It works, and it doubles your memory.

GRPO's answer is the one every teacher already uses:

group   = [sample_answer(prompt) for _ in range(G)]   # G answers, one prompt
rewards = [verify(a) for a in group]
for answer, reward in zip(group, rewards):
    A = (reward - mean(rewards)) / std(rewards)       # grade on the curve
    push_up(answer, by=A)                             # A is signed now

Grade the class against the class. No second model, no extra forward pass — you already had those rewards, and half the group comes out negative by construction. Nothing about the maths got better; the bill did. PPO's critic is a second network of roughly policy size with its own weights, gradients and Adam moments, and optimiser state is where RLHF memory actually goes. DeepSeekMath introduces GRPO in one setting: mathematical reasoning, where the reward is a verifier checking the final answer. If you can grade an answer with == you need no reward model, and now no critic either — the recipe DeepSeek-R1 was trained with.

The one formula

Ai = ( ri − mean(r1..G) ) / std(r1..G)
loss = −(1/G) Σi Ai · log π(yi|x) + β · KL( π ‖ πref )

That's it. The real paper writes the ratio-and-clip machinery PPO uses for multiple epochs on the same batch; strip that and this is what's left. Read it as pipeline stages:

StepShapeWhat it does
y1..G ∼ π(·|x)G answersThe group. One prompt, G samples. This replaces the critic
riG scalarsReward per answer. In DeepSeekMath, a verifier's grade
− mean(r)scalarThe baseline. Costs zero parameters. Half the group goes negative
/ std(r)scalarStep size stops depending on how spread out this group happened to be
Ai · log π(yi)scalarPolicy gradient. Push up if A > 0, down if A < 0
+ β · KLscalar ≥ 0The leash from the RLHF page — but added to the loss, not to the reward

Why a baseline exists at all

The script builds a toy world in the shape of the RLHF one: 6 prompts, 12 candidate answers each, and a reward. The reward here is a verifier — a direct 0-to-10 score, no learned reward model — because that's the setting GRPO was invented for. The policy is a softmax over the 12 answers, one row of logits per prompt, so the policy gradient is exactly A * (onehot(a) − probs) and I can measure the thing everyone talks about and nobody prints: the variance of the gradient estimate. 400 independent estimates, only the advantage changes.

Don't take my word for it. Here's the actual output:

every reward in this world is POSITIVE: min 0.027   max 9.351
gradient variance, G=8, 400 independent estimates:
  no baseline           E||g - Eg||^2 =    9.7489
  group-mean baseline   E||g - Eg||^2 =    2.1146
  reduction: 4.6x
both estimators point the same way on average:
  cosine(Eg_none, Eg_group) = 0.9961
The baseline changes nothing in expectation. That's the point. Both estimators aim at the same gradient — cosine 0.9961 between their means. Subtracting a number that doesn't depend on which answer you sampled is free, because the gradient of a distribution sums to zero against a constant. All a baseline buys is variance. Every baseline argument in RL, PPO's critic included, is an argument about which free constant to pick.

The group is the baseline

One group, printed so you can do the arithmetic yourself. Prompt 2, G = 8 samples from the reference policy, drawn with replacement — so answer 3 comes up four times. A group is just G more decodes of a prompt already in the batch. 

prompt 2, G=8 sampled answers: [ 3  7  7  3  0 11  3  3]
rewards            : [6.67  2.645 2.645 6.67  4.185 2.11  6.67  6.67 ]
group mean         : 4.7828
group std          : 1.9649
advantage = (r - mean) / std :
   answer  3  r  6.670  ->  A +0.9603
   answer  7  r  2.645  ->  A -1.0881
   answer  7  r  2.645  ->  A -1.0881
   answer  3  r  6.670  ->  A +0.9603
   answer  0  r  4.185  ->  A -0.3044
   answer 11  r  2.110  ->  A -1.3604
   answer  3  r  6.670  ->  A +0.9603
   answer  3  r  6.670  ->  A +0.9603
sum of advantages  : -0.000000   (zero, by construction)

(6.670 − 4.7828) / 1.9649 = 0.9603. Do it on a phone calculator. That's the algorithm. The / std isn't cosmetic: without it your update size depends on how spread out this group's rewards happened to be, which is a property of the prompt, not the answer.

The critic you delete

Same problem, same 400-estimate measurement, three baselines: none, a fitted value baseline (the PPO-style critic, handed the exact expected reward per prompt — I'm being generous to it), and the group mean. Then 300 steps of training with each. 

gradient variance, G=8, 400 estimates:
  no baseline                       9.7489
  fitted value baseline (PPO)       2.3416
  group-mean baseline (GRPO)        2.1146

parameters:
  policy (6 prompts x 12 logits)     72
  critic MLP (8 -> 16 -> 1)         161
  group baseline                      0   <- the point

300 steps, G=8, beta=0.02:
  reference policy         true reward 3.0131
  with critic              true reward 5.5041   KL 2.1683
  group baseline           true reward 5.5390   KL 2.5183

A 161-parameter critic against a 72-parameter policy, in a toy where the critic's job is embarrassingly easy. In a real run it's a second 7B network with its own Adam state. And it buys nothing here: the group baseline gets marginally lower variance and marginally more reward, for zero parameters.

Don't over-read the toy. My critic sees a clean 8-dimensional embedding; a real one reads text and has a hard regression to solve. The honest version: the critic isn't useless, it's expensive and fallible, and the group gives you most of it for free. Two things that can be wrong in your training run become one.

How big does the group need to be?

G is the one hyperparameter GRPO adds: a straight compute-versus-variance trade, G decodes per prompt per step. The two ends of the sweep are the interesting ones. 

  G   grad variance   final true reward   note
   1          0.0000              3.0131   advantage is identically 0
   2          2.5451              5.5031
   4          1.3656              5.5278
   8          0.6290              5.5390
  16          0.2994              5.5428
  32          0.1455              5.5442

  reference policy, untrained:  true reward 3.0131

G = 1 is worth staring at. With one sample the group mean is that sample, so every advantage is exactly zero, the gradient is zero, and the policy never leaves the reference: 3.0131 in, 3.0131 out. No error, no warning, no NaN — a training run that does nothing. You need two answers before there's a curve to grade on.

At the other end variance keeps halving as G doubles, but the reward column stopped moving at G = 8. You pay four times the decodes between 8 and 32 for the fourth decimal place. Real runs sit around 8 to 64 for the same reason.

The leash, moved into the loss

GRPO keeps the KL penalty — same leash, same job as on the RLHF page: stop the policy wandering somewhere the reward signal was never validated. Sweeping β does what you'd expect. 

  beta    final true reward   final KL(pi || pi_ref)
  0.00               5.5393                 2.5190
  0.02               5.5390                 2.5183
  0.10               5.5380                 2.5114
  0.50               5.4048                 1.9776
  2.00               3.8040                 0.1162

Note what this table does not show: β = 0 is fine here, and gets the best reward. In this world the reward is a verifier and the verifier is the truth — nothing to hack. The equivalent table on the RLHF page, where the reward is a learned model, has β = 0 climbing the reward model to 1.941 while true reward falls to 1.758. Verifiable reward versus modelled reward: that's why "does GRPO need the KL term" has two right answers.

The placement is the interview detail. RLHF folds the KL penalty into the per-sample reward; GRPO adds it as a term in the loss, over the whole distribution. Sounds like bookkeeping. It isn't: 

  beta 0.1  KL in loss   true 5.5380  KL 2.5114
  beta 0.1  KL in reward true 5.4884  KL 1.8684
  beta 0.5  KL in loss   true 5.4048  KL 1.9776
  beta 0.5  KL in reward true 5.3146  KL 1.2440

Same β, visibly different leash. Folded into the reward, the penalty goes through the group baseline with everything else — mean subtracted, std divided — so the coefficient you set is not the one you get; it's been rescaled by that group's reward spread. As a loss term its gradient is taken directly against the reference, and β means what it says.

The baseline must be per-prompt

Why the paper says group and not batch. Prompt 0 is easy (average reward 6.2), prompt 5 is hard (average 1.0). Take the mean over the whole batch instead of within each prompt's group, and look at what the advantage is now measuring. 

mean advantage per prompt, one batch (easy -> hard):
 prompt  mean reward   group baseline   batch baseline
   0          6.227            0.000            3.018
   1          3.470            0.000            0.261
   2          4.783           -0.000            1.574
   3          2.138           -0.000           -1.070
   4          1.645           -0.000           -1.564
   5          0.989            0.000           -2.220

gradient variance   group 2.1146   batch 3.6445

Read the last column. On prompt 5 every sampled answer has a negative advantage, the group's best included: the number now says "how hard was this prompt", not "how good was this answer". Probability drains off everything the policy sampled and onto whatever it didn't. On prompt 0, the reverse. 

final true reward per prompt after 300 steps:
 prompt   best possible   group baseline   batch baseline
   0              9.351            9.341            9.217
   ...
   5              1.884            1.879            1.822
  overall 5.5390 (group)  vs  5.4709 (batch)

Worse on every prompt, not just the hard ones, with 70% more gradient variance. In fairness it's still unbiased in the limit — a constant is a constant — but with a finite batch each update is about the prompt's difficulty rather than the answer's quality, which is what the numbers above are. "Group relative" is the name of the algorithm, and this is why.

DPO: ஏறுவதையே தவிர்க்கவும், ஏனெனில் அந்த objective-ன் optimum-க்கு ஒரு closed form இருக்கிறது; அதை ஒரு supervised loss ஆக மாற்றலாம். InstructGPT: இவை அனைத்தும் உள்ளே அமரும் மூன்று-நிலை pipeline. Reward model-ஐயோ, KL penalty-யையோ, policy gradient-ஐயோ நான் மீண்டும் பெறமாட்டேன். GRPO மூன்றையும் வைத்திருக்கிறது; அது மாற்றுவது நீங்கள் கழிப்பது என்ன என்பதுதான்.

வகுப்பிற்குள்ளேயே curve-ல் மதிப்பெண்

இதோ policy gradient — எல்லோரும் முதலில் எழுதும் வடிவம்: 

for answer, reward in sampled:
    push_up(answer, by=reward)     # reward 0..10, எப்போதும் நேர்மறை

Bug-ஐக் கண்டுபிடியுங்கள். ஒவ்வொரு reward-ம் நேர்மறை, எனவே sample செய்யப்பட்ட ஒவ்வொரு answer-ம் மேலே தள்ளப்படுகிறது — நல்லவையும் மோசமானவையும் சேர்த்து. நீங்கள் கற்க நினைத்தது வேறுபாடுகள்தான்; அவை ஒரு பெரிய மாறிலியின் மேல் உள்ள சிறு அலை. இது converge ஆகும்; நடைமுறையில் இது noise. எனவே நீங்கள் ஏதாவது ஒன்றைக் கழிக்கிறீர்கள். PPO-வின் பதில்: இரண்டாவது examiner-ஐ வேலைக்கு அமர்த்துங்கள். ஒரு value network — ஒரு critic, தோராயமாக policy-யின் அளவு — இந்த prompt எவ்வளவு score செய்ய வேண்டும் என்று கணிக்கப் பயிற்றுவியுங்கள், அதன் கணிப்பைக் கழியுங்கள். இது வேலை செய்கிறது, மேலும் உங்கள் memory-ஐ இரட்டிப்பாக்குகிறது.

GRPO-வின் பதில், ஒவ்வொரு ஆசிரியரும் ஏற்கனவே பயன்படுத்துவதுதான்:

group   = [sample_answer(prompt) for _ in range(G)]   # G answers, ஒரே prompt
rewards = [verify(a) for a in group]
for answer, reward in zip(group, rewards):
    A = (reward - mean(rewards)) / std(rewards)       # curve-ல் மதிப்பெண்
    push_up(answer, by=A)                             # A இப்போது குறியுடன்

வகுப்பை வகுப்பிற்கு எதிராகவே மதிப்பிடுங்கள். இரண்டாவது model இல்லை, கூடுதல் forward pass இல்லை — அந்த rewards ஏற்கனவே உங்களிடம் இருந்தன, மேலும் group-ல் பாதி அமைப்பாலேயே எதிர்மறையாக வருகிறது. கணிதத்தில் எதுவும் மேம்படவில்லை; bill-தான் மேம்பட்டது. PPO-வின் critic என்பது தோராயமாக policy அளவுள்ள இரண்டாவது network — அதற்கே சொந்தமான weights, gradients, Adam moments உண்டு; RLHF-ன் memory உண்மையில் போவது optimiser state-க்குத்தான். DeepSeekMath ஒரு அமைப்பில் GRPO-வை அறிமுகப்படுத்துகிறது: mathematical reasoning, அங்கே reward என்பது இறுதி விடையைச் சரிபார்க்கும் ஒரு verifier. ஒரு answer-ஐ == வைத்து மதிப்பிட முடிந்தால் உங்களுக்கு reward model தேவையில்லை, இப்போது critic-ம் தேவையில்லை — DeepSeek-R1 பயிற்றுவிக்கப்பட்ட செய்முறை இதுதான்.

Baseline ஏன் இருக்கிறது

Script ஒரு பொம்மை உலகை RLHF-ன் வடிவத்திலேயே கட்டுகிறது: 6 prompts, ஒவ்வொன்றுக்கும் 12 candidate answers, மற்றும் ஒரு reward. இங்கே reward ஒரு verifier — நேரடி 0-முதல்-10 மதிப்பெண், கற்கப்பட்ட reward model இல்லை — ஏனெனில் GRPO கண்டுபிடிக்கப்பட்ட அமைப்பு அதுதான். Policy என்பது 12 answers மேல் ஒரு softmax, ஒரு prompt-க்கு ஒரு வரிசை logits; எனவே policy gradient சரியாக A * (onehot(a) − probs). இதனால் எல்லோரும் பேசி யாரும் print செய்யாத ஒன்றை என்னால் அளக்க முடிகிறது: gradient estimate-ன் variance. 400 சுயேச்சையான estimates, advantage மட்டுமே மாறுகிறது.

என் வார்த்தையை நம்ப வேண்டாம். இதோ உண்மையான output:

every reward in this world is POSITIVE: min 0.027   max 9.351
gradient variance, G=8, 400 independent estimates:
  no baseline           E||g - Eg||^2 =    9.7489
  group-mean baseline   E||g - Eg||^2 =    2.1146
  reduction: 4.6x
both estimators point the same way on average:
  cosine(Eg_none, Eg_group) = 0.9961
Expectation-ல் baseline எதையும் மாற்றுவதில்லை. அதுதான் விஷயமே. இரு estimators-ம் ஒரே gradient-ஐ நோக்கியே குறிவைக்கின்றன — அவற்றின் means-க்கு இடையே cosine 0.9961. நீங்கள் எந்த answer-ஐ sample செய்தீர்கள் என்பதைச் சாராத ஒரு எண்ணைக் கழிப்பது இலவசம், ஏனெனில் ஒரு distribution-ன் gradient ஒரு மாறிலிக்கு எதிராகக் கூட்டினால் பூஜ்ஜியம். ஒரு baseline வாங்கித் தருவது variance மட்டுமே. RL-ல் உள்ள ஒவ்வொரு baseline வாதமும், PPO-வின் critic உட்பட, எந்த இலவச மாறிலியைத் தேர்ந்தெடுப்பது என்பது பற்றியதுதான்.

Group-தான் baseline

ஒரு group, நீங்களே கணக்குப் போட்டுப் பார்க்க print செய்யப்பட்டது. Prompt 2, reference policy-லிருந்து G = 8 samples, replacement-உடன் எடுக்கப்பட்டது — எனவே answer 3 நான்கு முறை வருகிறது. ஒரு group என்பது ஏற்கனவே batch-ல் இருக்கும் ஒரு prompt-ன் இன்னும் G decodes மட்டுமே.

நீங்கள் அழிக்கும் critic

அதே பிரச்சனை, அதே 400-estimate அளவீடு, மூன்று baselines: எதுவும் இல்லை, ஒரு fitted value baseline (PPO-பாணி critic, ஒவ்வொரு prompt-க்கும் சரியான expected reward கொடுக்கப்பட்டது — நான் அதற்குத் தாராளமாக இருக்கிறேன்), மற்றும் group mean. பிறகு ஒவ்வொன்றுடனும் 300 steps training.

72-parameter policy-க்கு எதிராக 161-parameter critic — critic-ன் வேலை வெட்கப்படும் அளவுக்கு எளிதான ஒரு பொம்மை உலகில். உண்மையான ஒரு run-ல் அது சொந்த Adam state-உடன் கூடிய இரண்டாவது 7B network. இங்கே அது எதையும் வாங்கித் தரவில்லை: group baseline சற்றே குறைந்த variance-ஐயும் சற்றே அதிக reward-ஐயும் பெறுகிறது, பூஜ்ஜிய parameters-க்கு.

பொம்மையை அளவுக்கு மீறிப் படிக்காதீர்கள். என் critic ஒரு சுத்தமான 8-பரிமாண embedding-ஐப் பார்க்கிறது; உண்மையான ஒன்று text-ஐப் படிக்கிறது, தீர்க்கக் கடினமான ஒரு regression வைத்திருக்கிறது. நேர்மையான வடிவம்: critic பயனற்றது அல்ல, அது விலை உயர்ந்தது, தவறக்கூடியது; group அதில் பெரும்பகுதியை இலவசமாகத் தருகிறது. உங்கள் training run-ல் தவறாகப் போகக்கூடிய இரண்டு விஷயங்கள் ஒன்றாகின்றன.

Group எவ்வளவு பெரிதாக இருக்க வேண்டும்?

GRPO சேர்க்கும் ஒரே hyperparameter G: நேரடியான compute-க்கு-எதிரான-variance பரிமாற்றம், ஒரு prompt-க்கு ஒரு step-க்கு G decodes. Sweep-ன் இரு முனைகள்தான் சுவாரஸ்யமானவை.

மறுமுனையில், G இரட்டிக்கும்போது variance பாதியாகிக் கொண்டே போகிறது, ஆனால் reward நெடுவரிசை G = 8-ல் நகர்வதை நிறுத்திவிட்டது. நான்காவது தசம இடத்திற்காக 8-க்கும் 32-க்கும் இடையே நான்கு மடங்கு decodes கட்டுகிறீர்கள். உண்மையான runs இதே காரணத்திற்காக 8 முதல் 64 வரை அமர்கின்றன.

இடம்தான் interview விவரம். RLHF, KL penalty-ஐ ஒவ்வொரு sample-ன் reward-க்குள் மடிக்கிறது; GRPO அதை loss-ல் ஒரு term ஆக, முழு distribution மேல் சேர்க்கிறது. கணக்கு வைப்பது போலத் தோன்றும். இல்லை:

ஒரே β, ஆனால் கண்ணுக்குத் தெரியும் அளவு வேறுபட்ட கயிறு. Reward-க்குள் மடிக்கப்பட்டால், அந்த penalty மற்ற எல்லாவற்றுடனும் சேர்ந்து group baseline வழியாகச் செல்கிறது — mean கழிக்கப்பட்டு, std வகுக்கப்பட்டு — எனவே நீங்கள் அமைத்த coefficient நீங்கள் பெறுவது அல்ல; அது அந்த group-ன் reward பரவலால் அளவு மாற்றப்பட்டது. ஒரு loss term ஆக இருக்கும்போது அதன் gradient நேரடியாக reference-க்கு எதிராக எடுக்கப்படுகிறது, β சொல்வதையே அர்த்தப்படுத்துகிறது.

"Group relative" என்பதுதான் algorithm-ன் பெயர், காரணம் இதுதான்.

मैं एक AI Engineer हूँ। मैंने models ship किए हैं, MLOps किया है। जब DeepSeek-R1 आया और सब "GRPO" कहने लगे, तो मुझे लगा यह कोई नया algorithm है जो मुझे शुरू से सीखना पड़ेगा। ऐसा नहीं है। यह RLHF पेज वाला policy gradient ही है, बस एक line बदली हुई — वह line जो baseline निकालती है। वही एक line आपके training job से एक पूरा दूसरा neural network मिटा देती है।

ध्यान दें: English technical words (policy gradient, baseline, critic, value network, advantage, group, KL, PPO, reward model…) मैंने वैसे ही रखे हैं। क्योंकि code में और बाक़ी papers में आपको वही शब्द दिखेंगे। समझ हिंदी में, शब्दावली English में।

यह पेज दो और पेजों पर टिका है। RLHF: इंसानी votes पर एक reward model fit करो, फिर policy से उस पर चढ़ो, और KL penalty आपको शुरुआती model के पास बनाए रखे। DPO: चढ़ाई छोड़ ही दो, क्योंकि उस objective के optimum का एक closed form है जिसे आप supervised loss में बदल सकते हैं। InstructGPT: वह तीन-चरणों वाली pipeline जिसके अंदर यह सब बैठता है। मैं reward model, KL penalty या policy gradient दोबारा नहीं निकालूँगा। GRPO तीनों रखता है; वह सिर्फ़ यह बदलता है कि आप घटाते क्या हैं।

क्लास के भीतर ही curve पर नंबर देना

यह रहा policy gradient, वही रूप जो सब पहले लिखते हैं: 

for answer, reward in sampled:
    push_up(answer, by=reward)     # reward 0..10, हमेशा धनात्मक

Bug पकड़िए। हर reward धनात्मक है, इसलिए हर sample किया गया answer ऊपर धकेला जाता है — अच्छे भी, बुरे भी। आप सीखना अंतर चाहते थे, और वह एक बड़े स्थिरांक के ऊपर की छोटी सी लहर है। यह converge तो होता है; व्यवहार में यह noise है। इसलिए आप कुछ घटाते हैं। PPO का जवाब: दूसरा examiner रख लो। एक value network — एक critic, लगभग policy जितना बड़ा — को train करो कि यह prompt कितना score करना चाहिए, और उसका अनुमान घटा दो। यह काम करता है, और आपकी memory दोगुनी कर देता है।

GRPO का जवाब वही है जो हर शिक्षक पहले से इस्तेमाल करता है:

group   = [sample_answer(prompt) for _ in range(G)]   # G answers, एक prompt
rewards = [verify(a) for a in group]
for answer, reward in zip(group, rewards):
    A = (reward - mean(rewards)) / std(rewards)       # curve पर नंबर
    push_up(answer, by=A)                             # A अब चिह्न सहित

क्लास को क्लास के ही सामने आँकिए। कोई दूसरा model नहीं, कोई अतिरिक्त forward pass नहीं — वे rewards तो आपके पास पहले से थे, और आधा group रचना से ही ऋणात्मक निकलता है। गणित में कुछ बेहतर नहीं हुआ; bill बेहतर हुआ। PPO का critic लगभग policy जितना बड़ा दूसरा network है, अपने weights, gradients और Adam moments के साथ — और RLHF की memory असल में optimiser state में ही जाती है। DeepSeekMath GRPO को एक ही setting में पेश करता है: mathematical reasoning, जहाँ reward एक verifier है जो अंतिम उत्तर जाँचता है। अगर आप किसी answer को == से आँक सकते हैं तो आपको reward model नहीं चाहिए, और अब critic भी नहीं — यही वह नुस्ख़ा है जिससे DeepSeek-R1 train हुआ।

जगह ही असली interview वाली बारीक़ी है। RLHF, KL penalty को हर sample के reward में मोड़ देता है; GRPO उसे loss में एक term की तरह, पूरे distribution पर जोड़ता है। सुनने में हिसाब-किताब लगता है। है नहीं:

वही β, पर साफ़ दिखने लायक़ अलग रस्सी। Reward में मोड़ देने पर वह penalty बाक़ी सब के साथ group baseline से होकर गुज़रती है — mean घटता है, std से भाग होता है — इसलिए जो coefficient आपने रखा वह वह नहीं है जो आपको मिलता है; वह उस group के reward-फैलाव से दोबारा नाप लिया गया है। Loss term के रूप में उसका gradient सीधे reference के विरुद्ध लिया जाता है, और β का मतलब वही होता है जो वह कहता है।

The code

NumPy for the mechanism — advantages, the policy gradient by hand, the variance measurements. A tiny CPU PyTorch loop for the training steps and the critic, because Adam and .backward() are not the idea. Every function under 35 lines.

def policy_gradient(logits, samples, advantages):
    """samples: (P, G) sampled answer indices. advantages: (P, G) scalars."""
    probs = softmax(logits)
    grad = np.zeros_like(logits)
    G = samples.shape[1]
    for p in range(logits.shape[0]):
        for i in range(G):
            onehot = np.zeros(logits.shape[1])
            onehot[samples[p, i]] = 1.0
            grad[p] += advantages[p, i] * (onehot - probs[p]) / G
    return grad


def sample_group(logits, G, rng):
    """Sample G answers per prompt, WITH replacement -- a group. (P, G)."""
    probs = softmax(logits)
    return np.stack([rng.choice(N_ANSWERS, size=G, p=probs[p])
                     for p in range(logits.shape[0])])


# ---------------------------------------------------------------------------
# STAGE 2 -- THE WHOLE PAPER. Two lines.
#
# A critic predicts "what should this prompt score?" and you subtract it.
# GRPO says: you already sampled G answers for this prompt. Their own mean IS
# that prediction, and it costs no parameters. Divide by the group's standard
# deviation so the update size does not depend on how spread out the rewards
# happened to be. Grading on a curve within the class.
# ---------------------------------------------------------------------------
def group_advantages(r, normalise=True):
    """r: (P, G) rewards for a group. Returns (P, G) advantages."""
    adv = r - r.mean(axis=1, keepdims=True)               # the group baseline
    if normalise:
        adv = adv / (r.std(axis=1, keepdims=True) + 1e-8)  # scale invariance
    return adv

And the training step, with the KL where GRPO puts it:

        chosen = lp.gather(1, torch.tensor(samples))              # (P, G)
        pg = -(adv_t * chosen).mean()
        kl = (lp.exp() * (lp - torch.log_softmax(ref, dim=-1))).sum(-1).mean()
        loss = pg + beta * kl                                     # KL in LOSS

On the maths anxiety

Less here than the notation suggests: a mean, a standard deviation, and one fact — subtracting a constant from the reward doesn't change where the gradient points on average. That fact is the whole justification for baselines, and the script demonstrates it rather than proving it (cosine 0.9961).

You don't need the policy gradient theorem. For a softmax policy the gradient of log π(a) with respect to the logits is onehot(a) − probs; for anything real it's loss.backward(). What is worth internalising is the word "variance", which RL people say constantly and which means one concrete thing: run the same estimator twice on the same policy and see how far apart the two answers land. That's grad_variance.

What I skipped: PPO's clipped ratio, which lets you take several optimiser steps on one batch of samples without the policy running away from them. Real GRPO keeps it. I take one step per batch, so the ratio is identically 1 and clipping is a no-op. Asked what GRPO inherits from PPO, that's the answer — the clipping, minus the critic.

Where to go next

This page gave you one thing: the baseline, and why deleting the critic is cheap. That's deliberately narrow. Three other places cover what I skipped.

  • DeepSeekMath: Pushing the Limits of Mathematical Reasoning in Open Language Models Shao et al., 2024. The original — GRPO is section 4.

    The reinforcement-learning section for the algorithm and the PPO comparison, then the unified-paradigm discussion — the best short account anywhere of how SFT, rejection sampling, DPO and PPO are one gradient with different data sources. Skip the corpus half.

  • Policy Gradient Algorithms Lilian Weng. The maths, laid out in order.

    The derivation I waved at: why a baseline leaves the gradient unbiased, where actor-critic comes from, what PPO's clipped objective does. Go here when "trust me, the constant cancels" stops being enough.

  • GRPO Trainer Hugging Face TRL. The implementation you'd actually run.

    My 12-answer softmax against a real one: token-level log-probs, reward functions you write yourself, num_generations (my G), and the config knobs for the KL term. Shows which of my simplifications the library also makes, and which it doesn't.

  • DeepSeek-R1: Incentivizing Reasoning Capability in LLMs via Reinforcement Learning DeepSeek-AI, 2025. GRPO at full scale.

    What this algorithm does pointed at a real model with rule-based rewards and no supervised warm-up. Read it for the reward design and the training-behaviour section; the algorithm is a back-reference to this page.

Order I'd take them in: RLHF first for the reward model and the leash, this page second for the baseline, then Lilian Weng if the maths is nagging you and R1 if the scale is. DPO fits anywhere after RLHF — it's the other way out of the same expense.
